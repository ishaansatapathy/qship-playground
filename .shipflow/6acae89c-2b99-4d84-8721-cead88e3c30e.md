# Add webhook delivery health dashboard

> Feature ID: `6acae89c-2b99-4d84-8721-cead88e3c30e`

## Request

Support and engineering need a simple admin page to see outbound webhook delivery status — last attempt time, HTTP status, retry count, and error message — without digging through server logs. Requirements: - New page at /admin/webhooks (protected — admin role only) - Table columns: endpoint URL, last status (success/failed), last attempt at, retry count, last error snippet (max 120 chars) - Filter by status: all / success / failed - Manual "Retry now" button per row (calls existing retry API) - Empty state when no webhooks configured - Use existing tRPC + Drizzle patterns in the monorepo — no new frameworks - Include at least one API route test and one UI smoke test Non-goals: editing webhook URLs, billing changes, or email alerts in v1. Success metric: support can diagnose a failed delivery in under 30 seconds.

## Goals

- Enable support to diagnose failed webhook deliveries in under 30 seconds.
- Reduce the time spent on troubleshooting webhook issues by 50% within the first month of launch.
- Increase the visibility of webhook delivery statuses to 100% of admin users accessing the dashboard.

## Acceptance Criteria

- [ ] Given the admin is logged in, when they navigate to /admin/webhooks, then they should see the webhook delivery health dashboard.
- [ ] Given there are no webhooks configured, when the admin accesses the dashboard, then they should see an empty state message.
- [ ] Given the admin is on the dashboard, when they filter by 'failed', then only failed webhook entries should be displayed.
- [ ] Given a webhook entry, when the admin clicks 'Retry now', then the retry API should be called and the status should update accordingly.
- [ ] Given a webhook entry with a last error message, when the admin views the dashboard, then the last error snippet should be displayed with a maximum of 120 characters.
- [ ] Given the admin is on the dashboard, when they view the table, then the columns should include endpoint URL, last status, last attempt, retry count, and last error snippet.

## Edge Cases

- If the retry API fails, the dashboard should display an error message to the admin.
- If there are network issues, the dashboard should handle the error gracefully and inform the user.
- If the last error message exceeds 120 characters, it should be truncated with an ellipsis.
- If the admin has no permissions, they should be redirected away from the dashboard.
