# Rate limit admin API endpoints

> Feature ID: `255dae6c-f263-4b43-a04b-893d6a07c620`

## Request

Product and security want rate limiting on all admin-only tRPC routes (billing, 
settings, feature approval) so a compromised session cannot spam expensive 
AI review or approval actions.

Requirements:
- Per-user limits: 60 requests/minute on admin routes, stricter on AI review (5/hour)
- Return 429 with Retry-After header when exceeded
- Log rate-limit hits to audit trail (user id, route, timestamp)
- Must not block normal read-only dashboard loads
- Add tests for limit enforcement and 429 response shape

We already use BetterAuth sessions and tRPC protectedProcedure — extend that stack, 
don't add a new auth library. Ship behind feature flag `RATE_LIMIT_ADMIN=true`.

## Goals

- Enable rate limiting of 60 requests/minute on all admin routes per user.
- Enable stricter rate limiting of 5 requests/hour on AI review endpoints.
- Reduce the number of abuse attempts on admin routes by 80% within the first month post-launch.
- Increase system stability by ensuring normal read-only dashboard loads are unaffected by rate limiting.

## Acceptance Criteria

- [ ] Given a user with a valid session, when they make more than 60 requests to admin routes in a minute, then they receive a 429 response with a Retry-After header.
- [ ] Given a user with a valid session, when they make more than 5 requests to AI review endpoints in an hour, then they receive a 429 response with a Retry-After header.
- [ ] Given a user exceeds their rate limit, when they check the audit trail, then their rate limit hits are logged with user id, route, and timestamp.
- [ ] Given a user is making requests, when they access read-only dashboard routes, then they are not affected by the rate limiting on admin routes.
- [ ] Given the feature flag `RATE_LIMIT_ADMIN=true`, when the application is deployed, then rate limiting is enforced on admin routes.

## Edge Cases

- Handle scenarios where a user rapidly alternates between admin and non-admin routes.
- Ensure that the rate limit resets correctly after the specified time period.
- Manage concurrent requests that may hit the rate limit threshold simultaneously.
- Gracefully handle logging failures without impacting user experience.
