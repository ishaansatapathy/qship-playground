# Add webhook delivery health dashboard

> Feature ID: `b53cbaed-95f8-41f2-8b1b-43b01e47b838`

## Request

Support and engineering need a simple admin page to see outbound webhook 
delivery status — last attempt time, HTTP status, retry count, and error 
message — without digging through server logs.

Requirements:
- New page at /admin/webhooks (protected — admin role only)
- Table columns: endpoint URL, last status (success/failed), last attempt 
  at, retry count, last error snippet (max 120 chars)
- Filter by status: all / success / failed
- Manual "Retry now" button per row (calls existing retry API)
- Empty state when no webhooks configured
- Use existing tRPC + Drizzle patterns in the monorepo — no new frameworks
- Include at least one API route test and one UI smoke test

Non-goals: editing webhook URLs, billing changes, or email alerts in v1.
Success metric: support can diagnose a failed delivery in under 30 seconds.

## Goals

- Enable support to diagnose failed webhook deliveries in under 30 seconds.
- Reduce the time spent on troubleshooting webhook issues by 50% within the first month of launch.
- Increase the visibility of webhook delivery statuses to 100% of admin users accessing the dashboard.
- Enable manual retries for failed webhooks with a success rate of 80% on the first retry.

## Acceptance Criteria

- [ ] Given the admin is logged in, when they navigate to /admin/webhooks, then they should see a table with the correct columns.
- [ ] Given the table is populated, when the admin filters by 'failed', then only failed webhook deliveries should be displayed.
- [ ] Given a failed webhook entry, when the admin clicks 'Retry now', then the retry API should be called and the status should update accordingly.
- [ ] Given no webhooks are configured, when the admin visits /admin/webhooks, then an empty state message should be displayed.
- [ ] Given a successful webhook delivery, when the last status is displayed, then it should show 'success'.
- [ ] Given a failed webhook delivery, when the last status is displayed, then it should show 'failed'.

## Edge Cases

- Handle scenarios where the webhook delivery history is empty.
- Manage cases where the retry API fails to respond.
- Ensure the dashboard correctly displays statuses when multiple webhooks are configured.
- Handle network errors gracefully when fetching webhook statuses.
